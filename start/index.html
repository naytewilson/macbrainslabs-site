The short version4 questions

What ran? Where was it assigned? Was it correct? Did it actually get faster?

Each question needs a different test. A result for one doesn’t prove the others.

The basics

The four questions.

Think of the Neural Engine as one place a computation can run. It doesn’t guarantee correct results or speed.

Build

What actually ran?

Core ML compiles a model graph. Small changes to the graph’s structure, its shapes or its diagnostics can change the compiled result. So I name the exact artifact and configuration.

How I document the artifacts ↗
Place

Where was it assigned?

Apple’s Core ML planner may report which operations are assigned to the ANE, the CPU or the GPU. That’s useful placement evidence. It isn’t a low-level trace that proves each operation physically ran on the ANE.

Look at a placement receipt ↗
Compare

Was the output correct?

A model can compile and get an ANE assignment, then still fail an output parity test. I compare exact outputs against declared fixtures, using defined numerical tolerances.

Read a passing and failing comparison ↗
Measure

Did it get faster?

Throughput depends on batch shape, dispatch cost, memory and what was timed. A speed measurement doesn’t validate model quality or the claims made about deployment.

See a speed hypothesis I got wrong ↗
Labels

What each label means.

Measured means it was observed under a named setup. Planner reported describes what the compiler planned, not an ANE hardware trace.

Source-bound means the published claim links to its artifacts or documented receipts. Verified archive means the published files and identifiers passed the stated integrity checks. That isn’t peer review.

Negative results, incomplete chains and changes to an earlier hypothesis belong in the research record.
