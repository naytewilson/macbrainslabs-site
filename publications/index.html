How a record qualifies

Six checks stand between upstream and this page.

This feed does not transcribe release text. It renders only structured fields that survived validation, and anything that could not be re-checked is surfaced as a degraded state, never silently smoothed. Draft and prerelease releases cannot enter.

  1. 01

    Published tag only

    Records enter as published GitHub release tags vX.Y.Z of the archive repository. Draft and prerelease releases are structurally excluded.

  2. 02

    Manifest at the tag

    Each release must carry manifest.json (schema 1.0) with source document fingerprints, explicit evidence limits and a DOI binding. A missing field stops the whole rebuild before anything is published.

  3. 03

    Bytes re-checked

    Release assets are downloaded at rebuild and hashed. Digests must equal those the release API registers, and SHA256SUMS must be internally consistent and agree.

  4. 04

    Provenance re-derived

    Every listed source document is fetched from the pinned site commit and its SHA-256 must equal the manifest fingerprint. A mismatch marks the record degraded, it is never deleted quietly.

  5. 05

    Registration cross-checked

    The manifest DOIs must point at a Zenodo record whose version DOI, concept DOI, title, publication date, creator ORCID and license match the manifest. Disagreement is shown, never averaged away.

  6. 06

    Last-known-good

    If upstream is unreachable, rate-limited, or a rebuild would downgrade a verified record, nothing is committed: this page keeps its previous snapshot and any failure stays visible in the repository's public workflow history. A new record that is not fully verified is also held — unverified entries are never auto-published.

Scope and limits

What this feed can and cannot claim.

An archived DOI is registration, not peer review. These records republish already-public summaries; the feed itself makes no experimental claims and contains no drafts or locally-unverified data.

Numeric results referenced by the records live on this site's own pages with their source receipts — see the research record and the field notes. The archiving repository macbrainslabs/ane-research-records carries its own integrity documentation. Correspondence is welcome at research@macbrainslabs.org.
