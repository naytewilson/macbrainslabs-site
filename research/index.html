The quantized Qwen model

A central experiment builds a 28-layer Qwen2.5-1.5B-Instruct path around four-bit lookup-table weights and native Core ML graph generation. The goal is more specific than just running on the Neural Engine. I want to keep the attention, projection, normalization and KV-state machinery in ANE-compatible tensor form. I also want to show the exact device each resulting operation is assigned to.

There are two Qwen artifacts in this record. I read placement from MLComputePlan on the production ANEMLL Core ML conversion of the 28-layer LUT4 model (qwen25_monolithic_full_lut4). I measured perplexity on the hand-written SwiftMIL model, which runs as two 14-layer halves that share KV. The production model’s infer function had 2,090 operations assigned to ANE and 79 assigned to CPU. Those counts are from the June 2026 measurement. A later shipped build of the same model line, recorded as converted on 21 October 2026, gave 2,147 ANE and 82 CPU in its infer function. E/001 shows both builds side by side. The residual CPU assignments belong to the language-model-head argmax tail.

Separately, the KV-state primitives I tested (slice_update, read_state, write_state and slice_by_index) were all assigned to ANE in the June infer function, 394 of 394. In the shipped prefill function, one read_state op is assigned to the CPU (56 ANE / 1 CPU), as shown on the placement evidence page. A CPU tail doesn’t invalidate a measured ANE-resident state path. The state path also doesn’t justify calling the whole graph 100% ANE.

state_ops = {
  slice_update:    56 / 56  # ANE / total
  read_state:      57 / 57
  write_state:     56 / 56
  slice_by_index: 225 / 225
}
infer.ops: ANE=2090 | CPU=79
observation: MLComputePlan assignment

The compiler constraints that matter most include FP16 rank-four graph geometry, integer gather indices, and append-only handling of Core ML’s external weight blobs. The failure cases that established those rules are in the Qwen note.

Measured batch throughput

The batch sweep measures aggregate throughput on the A18 Pro test system. It isn’t the token rate for one interactive user. Each batch value came from a compiled graph with matching physical input dimensions.

B=4 is the measured efficiency knee for this setup. The sweep timed single-function probe artifacts. Their output quality wasn’t validated, and the batch geometry hadn’t yet been carried into a deployable model. A later perplexity check on the B=4 probe, dated 3 July 2026, found its output logits roughly 1000 times larger than the B=1 model’s. The repository’s current records don’t resolve that (N/003).

I first proposed a 57.3 tok/s bandwidth ceiling. A batch-K-per-dispatch sweep on a probe model ruled it out, and so did a LUT2 experiment that cut the weights without increasing throughput. The updated result separates low-depth dispatch overhead from compute cost at 28 layers. Read the full analysis.

Liquid architecture parity

I evaluated a separate LFM block-pair S2 production artifact under .cpuOnly and .cpuAndNeuralEngine, then compared it with a pinned FP16 fixture. Placement assigned 743/743 compute operations to ANE for that sealed artifact. The native runner rejected non-finite output values, then computed cosine similarity, max absolute difference and relative L2 error.

A later LFM2.5-1.2B experiment is a separate case. Its layer slices each passed a stricter ANE gate (relative L2 ≤ 0.005), but they failed it once chained. See N/004.

What this doesn’t prove

Limits

These results don’t establish ANE residency for arbitrary transformer architectures, for every token-processing operation, or for every Core ML or compiler release. The assigned compute unit is a planner result that the API exposes. Numerical parity and measured end-to-end speed are separate experiments, each with its own conditions.

This research is still going. I keep hypotheses, performance projections and experimental stand-in shapes apart from hardware-qualified measurements. Negative results and retractions stay in the record. I don’t quietly replace them with flattering headlines.
