02Model under test

The measured artifact is qwen25_monolithic_full_lut4.mlmodelc. It is a Core ML conversion of Qwen/Qwen2.5-1.5B-Instruct produced with ANEMLL's Qwen2.5 converter: monolithic export, 512-token context, LUT4 palettization, argmax output. The model's metadata records coremltools 9.0 and ANEMLL v0.3.5.

Credit

The conversion that makes this model ANE-resident is ANEMLL's work. This record measures where that model's operations are assigned and what that says about the KV-state path. It does not claim the converter.

The compiled model is not distributed here. It is derived from the Qwen weights; its stored weight file is about 893 MB.

03Tools

04Rerun it

  1. Convert Qwen/Qwen2.5-1.5B-Instruct with ANEMLL's convert_monolith.sh at context 512 with LUT4 weights and argmax output, then compile the package with xcrun coremlcompiler compile.
  2. Build and run both tools against the compiled model's infer function:
swiftc -O ane_compute_plan.swift -o ane_compute_plan
swiftc -O kv_placement.swift -o kv_placement
./ane_compute_plan qwen25_monolithic_full_lut4.mlmodelc infer
./kv_placement qwen25_monolithic_full_lut4.mlmodelc infer

Compare the output with recorded_output.txt. These build commands are the standard way to compile a single Swift file. They were not rerun for this bundle.

Different converter flags can change the graph and therefore the counts. If your counts differ, the model's ANEMLL version, LUT settings and argmax setting are the first things to compare.

05What it shows

MLComputePlan is the compiler's assignment, not a hardware trace. These counts show where Core ML planned each operation of this build. They do not prove zero CPU work across the whole inference stack, and they do not transfer automatically to a different Core ML build.

The KV-state counts correct an earlier claim in the same research record. An earlier note said slice_update and write_state were an irreducible CPU floor. That came from a hand-written toy graph, not from a hardware limit. On this production graph, all four KV-state operators are assigned to the ANE.

06Gaps in the record

A reader should know what this bundle cannot supply.

  • No raw, timestamped log of the original run is in the record. The numbers come from the findings document and from the output block reproduced in the gate source.
  • The macOS build used for the run was not recorded.
  • The exact conversion command and ANEMLL commit for this artifact were not recorded. Recorded conversion scripts for related builds differ in batch and lm_head LUT flags.
  • No hash of the compiled model was recorded.
  • The record identifies the project's ANE as A18 Pro (H17), but the device is not stamped on this particular run.

Corrections and independent reruns are welcome at research@macbrainslabs.org.
