Archive path traversal

An untrusted proposal identifier became an archive destination. The recorded repair restores that boundary. A direct comparison shows why it matters.

What the defect allowed

An archive operation in private research automation built its destination from an untrusted proposal identifier. In the vulnerable revision, testing showed that a crafted identifier made the process overwrite a test-owned file outside the intended archive. The affected boundary was containment of proposal input within its assigned archive.

Input has to reach the proposal-ingestion path, and the effects are limited by the process’s filesystem permissions. This comparison doesn’t establish an internet-facing ingress, privilege escalation, exfiltration or an affected public deployment.

What the repair does

The recorded repair assigns sequence identifiers internally. It sanitizes identifiers, checks that the resolved path stays inside the archive, and refuses an archive destination that already exists. An affected copy should take that repair or equivalent containment controls, and it should be validated in its actual deployment environment.

Archive-before-append and attempted restoration improve error handling. They don’t establish crash-atomic behavior or protection against every concurrent filesystem race.

How I checked it

A later shell driver called the existing drain interface in separate, unchanged copies of each source revision. Each source got a benign control and a traversal input, each in its own disposable directory. The target sentinel belonged to the test. It stayed in the directory the test owns, outside the copied archive.

All six runs recorded exit status 0. The public JSON keeps the before and after sentinel hashes. Only the pre-repair traversal changed its target’s bytes. Exit status alone would have missed the problem.

The current path suite passed 14/14 checks on the pinned later source. The same fixture on the pre-repair source passed 11 checks and failed 3. Its sentinel assertion also passed on the pre-repair source. So the suite comparison alone couldn’t show the overwrite. The separate direct probe gives that contrast.
