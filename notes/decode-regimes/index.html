The ceiling was an illusion.

A plausible throughput explanation failed when its predicted behavior did not appear under a controlled change in input geometry and weight size.

01The appealing first hypothesis

The compiler's analytics.json surfaced an internal DRAM bandwidth planning figure of 51.2 GB/s. Dividing that number by the as-stored 893 MB external weight file yielded approximately 57.3 tokens/sec, close to an early peak. It seemed to support a hard bandwidth ceiling.

But dimensional plausibility is not a causal test. The calculation predicted that halving the bytes read per token would increase throughput, and that increasing genuine work per dispatch would remain constrained by the same byte rate.

02Counter-experiments

Two observations contradicted that simple model. First, reduced-size LUT2 weights did not produce the corresponding speedup. Second, a K sweep (batch K per dispatch, on a probe model) moved aggregate useful work more rapidly than the supposed throughput limit permitted. The original “57.3 tok/s ceiling” was retracted as a K=1 coincidence, not treated as an ANE architectural law.

Subsequent work refined the regime analysis: fixed per-call dispatch costs matter at shallow graphs, but at 28-layer production depth per-layer compute dominates more of the total step time. The productive lever is demonstrated multi-lane execution, not arithmetic on weight bytes alone.

These are aggregate throughputs over five-round interleaved steady-state measurements. The B=4 value is the practical default for the 8 GB machine. It is not an individual-stream token rate, nor an end-to-end app UX measurement.

04What qualifies as a speed result

ACCEPT only if:
  1. compiled input tensor has real [B, ...] shape
  2. elapsed time scales with actual B work
  3. reported tokens = work actually executed
  4. source artifact and device are named

REJECT:
  fixed [1,1] model + posthoc divide by K
  synthetic tokens from a benchmark argument
  projected tokens/sec treated as measured

The project rejected a K=16 throughput claim derived from a shape-locked [1,1] compiled model and a post-hoc divisor. Its reported wall time was flat while its headline token rate increased, indicating arithmetic rather than additional hardware work.

05What to take forward

Conclusion · bounded

On the tested Qwen decode substrate, real batch geometry increases aggregate throughput. At shallow depth dispatch overhead is material; at 28 layers computation load changes the limiting regime. No single constant extracted from a compiler report should be published as a universal throughput ceiling.

Source evidence: ane-re/docs/FINDINGS.md §§5, 7–9, 13; ANE-RE decision ledger D001, D028, D040, D143, D264. Performance numbers depend on the recorded device, software and thermal conditions.
