# MacBrains Labs — research site

Static, dependency-free public website for independent Apple Silicon and Apple Neural Engine research.

**URL:** https://macbrainslabs.org

## Evidence and claims

This is an editorial research front-end, not an official Apple-affiliated or government-affiliated laboratory. Research summaries come from separate ANE-RE internal measurements and receipts. This site does not contain private source code, model weights, personal contact address, credentials, or internal machine paths.

- **Qwen2.5 1.5B / 28L LUT4:** MLComputePlan inference assignment 2,090 ANE / 79 CPU (3.6% CPU argmax tail), according to `docs/FINDINGS.md`.
- **Qwen batch sweep:** 45.4 / 68.1 / 102.1 / 125.8 aggregate tok/s at B=1/2/4/8, per D028.
- **LFM S2:** 743/743 ANE-assigned compute operations on a specific sealed production graph, separate from a divergent 46-output diagnostic graph; source receipt `LFM_S2_NATIVE_PARITY_2026-07-18.md`.
- **Quantized quality:** 16.8033 perplexity on WikiText-2 for named Qwen LUT4 experiment, D263.

Terms like "ANE placement" refer to Core ML MLComputePlan assignment, *not* direct chip tracing.

## Structure

- `index.html`: home and overview
- `research/`: source-bound results
- `methods/`: experimental methodology
- `notes/`: field-note index and detailed technical notes
- `publications/`: publication archive feed; generated by `scripts/update-publications.mjs`
- `evidence/qwen-placement/`: evidence bundle E/001 (placement tools, recorded output, provenance)
- `contact/`: public research correspondence
- `404.html`: not-found page GitHub Pages serves for unknown paths (`noindex`)
- `security/`: project-owner advisories and sanitized observation summaries for private tooling; separate from ANE measurement evidence
- `styles.css`: styling for every page except the home page, light and dark via `prefers-color-scheme`, system fonts only (no client-side JavaScript)
- `home.css`: home page styling (v14 design: dark opening, paper research folios), system fonts only
- `assets/`: home media. `notch-v13.mp4` is the Notch animation master, shipped byte-identical (SHA-256 `6fc253ce2cf495e2ec9f922495da372e4a9ec914146c8546a9dc618c2845f073`, 8,574,149 bytes, 1350×1890, 24 fps, H.264, no audio track). It plays once on its own when it scrolls into view, muted, inline and without a player; `home.js` (the site's only script, home page only) then hands off to `notch-loop.mp4`, eight cycles of master frames 463–481 encoded the same way (1,311,937 bytes), which loops forever so the emblem keeps swaying, and pauses both videos while they are off screen. When the browser refuses to play video without a tap (`NotAllowedError`, for example iOS Low Power Mode), `home.js` plays `notch-img.mp4` in an `<img>` instead: the walk followed by fifteen sway cycles (767 frames, 31.96 s, 9,940,957 bytes, same H.264 settings), which Safari plays and repeats like an animated image with no tap. Browsers that cannot play MP4 in `<img>` get the final still with `notch-sway.avif` over it, a 280×1264 crop of the sway frames, and the first tap or key press plays the walk. A `play()` interrupted by scrolling away (`AbortError`) is ignored. Hardware video decoding keeps the motion at real speed. `notch-first.webp` is its first frame (poster), `notch-still.webp` its last frame (lossless), shown instead under reduced motion. `brand-mark-96.png` is the brand mark downscaled from the 512 px original
- `favicon.svg`: vector mark

## Hosting

GitHub Pages branch `main` from root, custom domain `macbrainslabs.org`.
DNS A records for GitHub Pages must be configured at the registrar **without** replacing MX, SPF, DKIM, DMARC or other mail settings. The custom domain has been live with enforced HTTPS since October 29, 2026. Verify DNS, TLS and every link after future deployments.

No tracking scripts, cookies, analytics or external assets. Structured data is inline JSON-LD (`application/ld+json`), which browsers do not execute. It describes only content shown on the page and identifiers already linked from it. Article dates are full ISO 8601 datetimes with an offset: `datePublished` is the time of the commit that first put the page on `main`, and `dateModified` is the time of its last content change.

## Publication feed

`/publications/` lists published archive releases of the public research record (from the separate `macbrainslabs/ane-research-records` repository). It is **static HTML with no client-side JavaScript**: a dependency-free Node script (`scripts/update-publications.mjs`) regenerates the page and its `publications.json` from upstream, and a scheduled GitHub Actions workflow (`.github/workflows/publications.yml`) reruns it roughly every six hours, committing only when the records change.

The feed does not transcribe release text. For every record it **re-derives** at rebuild time:

- that the release is a published `vX.Y.Z` tag (drafts and prereleases are excluded structurally);
- the SHA-256 digest of each release asset, re-downloaded locally and compared with both the digests registered in the release API and the archive's own `SHA256SUMS`;
- every source-document fingerprint in the record's `manifest.json` (schema 1.0), by fetching the pinned site commit's bytes and re-hashing them; a mismatch marks the record degraded rather than deleting it;
- the DOI binding against the Zenodo registration (version DOI, concept DOI, title, publication date, creator ORCID and license); for releases whose tagged manifest predates DOI issuance, the candidate DOI comes from the current citation file and is accepted only when Zenodo's registration itself binds it to that exact tag and repository.

The registered DOI state is always **derived from the verified Zenodo record** (`registered_state` in `publications.json`); the status string in the tagged manifest is preserved as archival provenance only (`tagged_manifest_doi_status`) and never describes the current registration.

Every URL is validated against a host allowlist, and upstream text that fails sanitization stops the rebuild rather than being partially rendered.

**Last-known-good:** the feed publishes only independently verified records. A rebuild that fails, is rate-limited, would carry **any** record that is not fully verified — a previously verified record re-deriving degraded (even over changed upstream data), or a new record that is not fully verified — or would remove records silently holds the **whole** update: nothing is published, the previously committed snapshot stays live, and the workflow failure is visible in this repository's Actions history. The rule (`scripts/test-publications-lkg.mjs`, 14 adversarial cases, run as a CI step before every rebuild) compares only the upstream data core (re-derived verification state is excluded from comparison), but a data change never lowers the verification bar. Records never disappear from the feed on their own; removal requires a human-reviewed commit.

## Regression checks

`node scripts/check-site.mjs` validates every root-relative internal link, sitemap URL, metadata canonical, published page, required asset, the contact address on every page, that the home placement figure draws exactly as many cells as its stated operation counts, and that the evidence bundle's tool files and counts match its `provenance.json`. It also parses every JSON-LD block, checks that each BreadcrumbList matches the visible breadcrumb trail, that each TechArticle's headline, description and dates match what the page shows (dates as full datetimes with an offset, a visible Revised date only for a later-day change), that titles and descriptions are unique, and that `404.html` stays `noindex` and out of the sitemap. The publication feed has its own contract checks: `publications.json` structure and allowlisted URLs, verification self-consistency (a record may only be shown as verified when every guard passed at rebuild), binding between the JSON, the feed page and the home summary block, and a site-wide guard that every `<script>` tag is JSON-LD and no inline event handlers exist. Run `node scripts/check-site.mjs --live` after GitHub Pages deployment to verify the public custom-domain copy. GitHub Actions runs the local test at every PR and on the main branch.
